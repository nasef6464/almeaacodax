# عقد إجراءات المهارة داخل التأسيس — ALMEAA

الحالة: سياسة تطوير عامة معتمدة ضمن PR #432؛ يظل اعتماد الإنتاج مرتبطًا بنجاح CI والدمج والنشر.

## المصدر الوحيد للتوجيه
تستخدم مهارات الطالب في **تقاريري، النتيجة بعد الاختبار والتدريب، تفاصيل أكثر، تفاصيل الاختبارات السابقة، والمسار الذكي** مرجعًا واحدًا: `Topic` المرتبط بالمهارة عبر `resolveFoundationSkillTarget`. لا تنشئ شاشة الطالب موجهًا بديلًا أو تبحث عن عنوان مشابه من تلقاء نفسها.

تعيد `buildCanonicalFoundationSkillActions` ثلاثة روابط لنفس `pathId / subjectId / topicId / skillId`، ويختلف فقط معامل `content`:
- فيديو: `tab=skills&content=lessons` لعرض قائمة كل الشروحات والفيديوهات داخل الموضوع، **دون تشغيل تلقائي**.
- تدريب: `tab=skills&content=quizzes` لعرض تدريبات نفس الموضوع، **دون بدء اختبار تلقائي**. تشغيل التدريب لاحقًا يتم بإجراء صريح داخل الموضوع.
- ملف الدعم: `tab=skills&content=support` للمرفقات الداعمة في نفس الموضوع.

عند ربط فيديو ثانٍ أو تدريب جديد أو ملف دعم جديد بالموضوع، يظهر في تبويبه الحالي دون حاجة إلى تغيير روابط التقارير. وينطبق العقد تلقائيًا على المواد القادمة التي تدخل ضمن نموذج التأسيس، دون تخصيص باسم مادة أو بنك.

## ضوابط السلامة
- المهارة الفرعية تتطلب ربط `Topic.skillId` أو `Topic.skillIds` صريحًا ضمن نطاق المادة/المسار؛ **لا fallback بالاسم للطالب**.
- إن تعذر تأكيد الموضوع، الإجراء غير متاح مع بيان «غير مرتبط بعد» بدلًا من فتح `/courses` أو اختبار أو مادة أخرى.
- يحتفظ الموضوع نفسه بحقوق الوصول التجاري والمجاني والمدفوع؛ الرابط لا يمنح وصولًا إضافيًا.
- نتيجة التدريب الأصلية و`skillsAnalysis` و`SkillProgress` مصادر حقيقة الأداء، ولا يعاد اختراع نسبة أو نتيجة.
- القياس اللاحق مرحلة منفصلة عن التدريب: يُفتح اختبار فعلي مخصص للمهارة بناءً على طلب الطالب، وليس من زر «تدريب» أو «فيديو».
- يجب أن تميز واجهة التقدم بين فتح الفيديو فعليًا وبين مشاهدة مكتملة؛ ومقارنة النسب لا تظهر إلا عندما توجد محاولتان حقيقيتان لنفس المهارة.

## معايير اختبارات التراجع
يفشل اختبار العقد إذا:
1. تغيّر أحد إجراءات التأسيس إلى `/courses` أو `/quiz` المباشر.
2. غاب `topicId` عن الرابط الموثوق أو اختلط `pathId / subjectId / skillId`.
3. تسبب الضغط على رابط «فيديو» في تشغيل تلقائي، أو «تدريب» في بدء اختبار تلقائي.
4. أظهر التقرير رابطًا قابلًا للنقر لمهارة فرعية دون ربط صريح.
5. اختفت مهارات الطالب بسبب حد ثابت؛ الواجهة يمكنها عرض أول 12 مع خيار إظهار الجميع، لكن لا تحذف البيانات.

## مهمة قبول مؤجلة بطلب صاحب المشروع
**بعد اكتمال PR #432 ونشره:** إجراء Audit شامل للمحتوى الفعلي لكل مادة/مهارة: التطابق الدقيق Skill ↔ Topic، حضور الشروحات، التدريبات، ملفات الدعم، صلاحيات المجاني/المدفوع، ثم الضغط الفعلي على روابط الطالب، مع تقرير PASS/FAIL وتسميات الحالات غير المرتبطة. لا تُعلن نسبة تغطية أو إغلاق قبل فحص الإنتاج الفعلي. عند ظهور Topic غير مربوط يمكن اقتراح مطابقة الاسم للمراجعة البشرية فقط، وليس توجيه الطالب إليه.
