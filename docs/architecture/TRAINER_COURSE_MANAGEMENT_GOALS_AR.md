## القرار المنتجـي

لا نبني نظام مستخدمين أو دور مدرب جديدًا. مدرب المنصة يظل `User` بدور
`teacher`، وتحدد صلاحيات إنتاجه بواسطة `managedPathIds` و
`managedSubjectIds`. معلم المدرسة يظل مميزًا بواسطة السياق المدرسي، ويمكن
للحساب نفسه امتلاك السياقين دون ترحيل شامل للأدوار.

نبني أربع مساحات مترابطة:

1. إدارة المستخدمين للحسابات والأدوار والعلاقات العامة.
2. إدارة المدربين للتخصص والتكليف والإنتاج والحالة.
3. إدارة الدورات للمستودع والملكية ودورة الاعتماد والنشر.
4. لوحة المدرب لأعماله داخل النطاق المصرح فقط.

حلقة التشغيل المستهدفة:

`إنشاء حساب مدرب → إسناد مسار/مواد → إنشاء محتوى → إرسال للمراجعة → اعتماد المدير → النشر → قياس الأداء`

## الحالة الحالية المثبتة قبل التنفيذ

### يعمل ويمكن إعادة استخدامه

- هوية «مدرب منصة» موجودة على الدور `teacher`.
- نطاق المدرب يفرض خادميًا على Course وLesson وQuestion وQuiz وLibrary.
- النطاق الفارغ يفشل مغلقًا، والوصول خارج النطاق يرجع `403`.
- Course يدعم الملكية والمدرب المكلف ونسبة المشاركة وحالات الاعتماد.
- إنشاء وتعديل وحذف الدورات متصل فعليًا بالـAPI وقاعدة البيانات.
- إدارة المستخدمين تدعم الإنشاء والبحث والترقيم وتغيير الدور والحذف وربط
  المدارس والفصول والأبناء وتكليف المدرب بالمسارات والمواد.
- حذف المستخدم يحمي المدير الحالي وآخر مدير، وتغيير الدور ينظف العلاقات
  القديمة ذات الصلة.

### الفجوات الحقيقية

- منتقي المدرب في منشئ الدورة يعتمد على `useStore().users`، وهي قائمة قد تكون
  فارغة أو تمثل صفحة واحدة فقط من إدارة المستخدمين.
- اختبار Course Builder الحالي يثبت وجود عنصر الاختيار ولا يثبت جلب حسابات
  مدربين حقيقية.
- إدارة الدورات مدفونة داخل المسار والمادة ولا توجد كمساحة رئيسية موحدة.
- لوحة مدرب المنصة لا تحتوي «دوراتي» ولا تمنحه رحلة كاملة لإنشاء دورة ومتابعة
  مراجعتها.
- لا توجد مساحة «إدارة المدربين»؛ الموجود ملخصات مشتقة من بيانات واجهة قد
  تكون غير مكتملة.
- مراجعة واعتماد محتوى المدربين موزعة، ولا توجد قائمة خادمية كاملة قابلة
  للبحث والترقيم وملاحظات المراجع.
- بعض تحديثات المستخدمين تفاؤلية ولا تنتظر إثبات الحفظ، والعمليات الجماعية
  ترسل طلبًا منفصلًا لكل مستخدم.
- إحصاءات الأدوار في إدارة المستخدمين مشتقة من الصفحة المحملة وليست إجماليات
  النظام.
- Course CRUD يسمح حاليًا بدور `supervisor`، بينما Managed Content Scope يطبق
  على `teacher` فقط؛ يجب حسم هذا التسرب واختباره قبل توسيع الواجهة.

## ثوابت التنفيذ

- لا User system جديد ولا Trainer model جديد في MVP.
- لا تغيير شامل لدور `teacher` ولا كسر لمساحة معلم المدرسة.
- لا اعتماد أو نشر من الواجهة فقط؛ القرار Server-authoritative.
- لا مدرب يرى أو يعدل محتوى خارج المسارات أو المواد المسندة.
- الاعتماد منفصل عن النشر والظهور للطالب.
- لا نعتمد على محتوى Store جزئي لبناء قوائم علاقات أو إحصاءات إدارية.
- لا نعرض أدوات المدير في لوحة المدرب حتى لو كان الخادم سيرفض العملية.
- كل هدف يغلق باختبارات موجبة وسلبية ودليل runtime مناسب وتحديث حالة التنفيذ.
- لا يبدأ هدف تالٍ قبل امتلاك الهدف السابق رحلة usable مثبتة.

## G13 — دليل المدربين وسلامة تعيين الدورة

> الحالة: `CLOSED / VERIFIED` في `487693b223c0355fc914eedd3c34525b21566914`.
> دليل CI: [Platform V3 Backend Integration Gate #34507622744](https://github.com/nasef6464/almeaacodax/actions/runs/34507622744) PASS على Mongo معزول وAPI حي.

### الهدف

إصلاح العيب الحالي بحيث يختار المدير مدربًا حقيقيًا ونشطًا من الحسابات، مع
منع أي تعيين غير صحيح في الخادم.

### نطاق التنفيذ

- إنشاء Trainer Picker محلي لا يعتمد على قائمة المستخدمين العامة.
- جلب `teacher` من API ببحث خادمي وترقيم صفحات وحالات loading/error/empty.
- التمييز بين:
  - مدرب منصة مهيأ بنطاق محتوى.
  - حساب هجين مدرب منصة + معلم مدرسة.
  - معلم مدرسة فقط.
  - حساب teacher غير مهيأ.
- يعرض منتقي الدورة مدربي المنصة النشطين المؤهلين فقط.
- الإبقاء على خيار «فريق المنصة» بصورة صريحة، وليس باعتباره مستخدم Admin.
- التحقق خادميًا عند إنشاء أو تعديل الدورة من أن `assignedTeacherId`:
  - يشير إلى مستخدم موجود ونشط.
  - دوره `teacher`.
  - يملك المسار أو المادة الخاصة بالدورة.
- رفض التكليف المخالف برسالة عربية قابلة للعرض في الواجهة.
- عدم تحميل كل المدربين داخل Global Store.

### معايير القبول

- تظهر الحسابات الحقيقية للمدربين في إنشاء الدورة حتى لو لم يفتح المدير تبويب
  إدارة المستخدمين.
- يمكن البحث عن المدرب بالاسم أو البريد.
- يحفظ المدرب المكلف ويعود من API/DB بعد إعادة التحميل.
- مدرب الرياضيات لا يمكن تكليفه بدورة خارج نطاقه.
- الحساب الموقوف أو غير المهيأ لا يقبل التكليف.
- اختبارات موجبة وسلبية تغطي API والواجهة والعلاقة المحفوظة.

### دليل الإغلاق

- منتقي المدرب لم يعد يقرأ `useStore().users`؛ يطلب دليلًا خادميًا مستقلًا
  قابلًا للبحث والترقيم.
- الدليل يعيد `teacher` النشط الذي يملك مسارًا أو مادة مسندة فقط، ولا يمكن
  قراءته بهذه الصيغة إلا لمدير المنصة.
- الخادم يتحقق من أن المدرب موجود ونشط ودوره `teacher` وأن الدورة تقع داخل
  نطاقه قبل حفظ التكليف.
- اختبر CI HTTP الفعلي: ظهور مدرب مؤهل، إخفاء teacher غير مهيأ وموقوف، تكليف
  صحيح محفوظ، رفض تكليف خارج النطاق، رفض المدرّب الموقوف، ومنع المدرب من
  إعادة تعيين دورة بطلب مباشر.
- local: server check/build، TypeScript مستقل لمنشئ الدورة،
  `smoke:course-builder` و`smoke:account-workspaces-g7` PASS.
- فحص TypeScript الشامل للواجهة بقي محجوبًا بخطأ parsing سابق وغير مملوك في
  `AnnouncementAdsManager.tsx`؛ لم يكن ضمن تغييرات G13، بينما فحص الملف
  المتأثر مباشرة نجح.

## G14 — مركز إدارة المدربين

### الهدف

إضافة مساحة رئيسية للمدير لإدارة المدربين ونطاقاتهم وأعمالهم دون تكرار إدارة
المستخدمين.

### نطاق التنفيذ

- بند رئيسي «إدارة المدربين» في لوحة مدير المنصة.
- قائمة خادمية قابلة للبحث والترقيم والتصفية حسب:
  - نشط/موقوف/غير مهيأ.
  - المسار.
  - المادة.
  - منصة فقط/هجين.
- تعديل المسارات والمواد مع انتظار نتيجة الخادم وإظهار نجاح أو فشل.
- ملف مدرب يعرض:
  - بيانات الحساب وحالته.
  - المسارات والمواد المسندة.
  - الدورات والدروس والفيديوهات والأسئلة والاختبارات وملفات المكتبة.
  - عدد المسودات والمعلق والمعتمد والمرفوض والمنشور.
- فتح محتوى المدرب مباشرة داخل مركزه المناسب.
- إيقاف وإعادة تفعيل المدرب مع Audit Log.
- بناء Read Model/endpoint إداري للتجميعات بدل حسابها من Bootstrap جزئي.

### معايير القبول

- يرى المدير كل المدربين وإجماليات صحيحة بصرف النظر عن الصفحة المفتوحة.
- تعديل نطاق المدرب يؤثر فورًا على صلاحيات الخادم.
- يستطيع المدير الوصول إلى دورات ومحتوى مدرب بعينه من ملفه.
- لا يستطيع غير Admin الوصول لمساحة الإدارة أو بيانات مدربين خارج صلاحيته.

## G15 — مركز الدورات ولوحة «دوراتي»

### الهدف

تحويل إدارة الدورات إلى رحلة كاملة للمدير والمدرب مع فصل الأدوات حسب الشخصية.

### نطاق المدير

- بند رئيسي مستقل «إدارة الدورات» يعرض جميع الدورات.
- بحث وترقيم وتصفية بالمدرب والمسار والمادة وحالة الاعتماد والنشر.
- تغيير المدرب المكلف بعد تحقق الخادم.
- تحديد نسبة المدرب بصورة Admin-only.
- اعتماد أو رفض أو طلب تعديل مع ملاحظة.
- إبقاء إدارة دورات المادة متاحة كمدخل سياقي، مع توحيدها مع المصدر المركزي.

### نطاق المدرب

- بند «دوراتي» في لوحة مدرب المنصة.
- إنشاء وتعديل داخل نطاقه فقط.
- دعم دورة الحياة:
  `draft → pending_review → approved/rejected → published`.
- حفظ مسودة وإرسال للمراجعة وإعادة الإرسال بعد التعديل.
- عرض ملاحظات المراجع ومعاينة صفحة الطالب.
- إخفاء أدوات الاعتماد والنشر ونسبة الإيراد وتعيين مدرب آخر.

### معايير القبول

- ينشئ المدرب دورة داخل مادته، يحفظها، يرسلها، ويراجعها المدير.
- لا تظهر الدورة للطالب قبل الاعتماد والنشر.
- الرفض أو طلب التعديل يصل للمدرب مع الملاحظة.
- لا يستطيع المدرب اعتماد أو نشر دورته بطلب API مباشر.
- لا يستطيع المدرب تعديل دورة مدرب آخر أو تغيير ملكيتها.

## G16 — مركز اعتماد محتوى المدربين وحسم RBAC

### الهدف

توحيد حوكمة محتوى المدربين وإغلاق مسارات الصلاحيات غير المقصودة.

### نطاق التنفيذ

- مركز مراجعة موحد للدورات والدروس والفيديوهات والأسئلة والاختبارات والمكتبة.
- قائمة خادمية كاملة ببحث وترقيم وتصفية بالنوع والمدرب والحالة.
- توحيد الحالات مع انتقالات خادمية مصرح بها.
- ملاحظات مراجعة وسجل المراجع وتاريخ القرار.
- منع ظهور أي محتوى للطالب ما لم يكن معتمدًا ومنشورًا وفق سياسة نوعه.
- تدقيق Course/Lesson/Question/Quiz/Library CRUD لكل من Admin وTeacher و
  Supervisor.
- إزالة `supervisor` من أي تأليف عام غير مقصود، أو تقييده صراحة بسياق مدرسي
  موثق إذا كان هناك استعمال قائم يحتاجه.
- Cross-role وcross-scope negative tests إلزامية.

### معايير القبول

- كل عنصر معلق يظهر مرة واحدة في مركز الاعتماد.
- لا يستطيع المدرب تغيير حقول المراجعة أو النشر أو الإيراد.
- لا يملك المشرف تأليف محتوى منصة عامًا عبر API مباشر.
- قرارات المراجعة محفوظة وقابلة للتتبع.

## G17 — تقوية إدارة المستخدمين

### الهدف

جعل إدارة المستخدمين دقيقة وآمنة وقابلة للتوسع دون أن تفسد بيانات بقية
اللوحات.

### نطاق التنفيذ

- فصل قائمة الصفحة الحالية عن `useStore().users` أو تطبيق Entity Cache merge
  واضح بدل استبدال المخزن كله.
- endpoint ملخص يعطي إجماليات الأدوار والحالات والشخصيات الفعلية.
- تحويل تعديل الاسم والحالة ونطاق المدرب وربط ولي الأمر إلى أوامر awaited مع
  loading/success/error لكل صف.
- endpoint عمليات جماعية آمن يعيد تقريرًا لكل مستخدم بدل fire-and-forget.
- منتقيات بحث خادمية للطلاب والمدربين عند إنشاء العلاقات الكبيرة.
- تعريب كل قوائم الإجراءات والرسائل.
- المحافظة على منع حذف الحساب الحالي وآخر Admin وتنظيف العلاقات عند تغيير
  الدور.
- تحذير ومنع الالتباس عند إنشاء teacher بلا سياق مدرسة أو نطاق منصة.
- عقود RBAC وعزل المدارس للطلاب والمشرفين ومديري المدارس وأولياء الأمور.

### معايير القبول

- البحث أو تغيير الصفحة في إدارة المستخدمين لا يفرغ قوائم مستخدمي بقية النظام.
- الإحصاءات تطابق إجماليات قاعدة البيانات.
- فشل الحفظ يعيد الصف لحالته الصحيحة ويعرض السبب.
- العملية الجماعية تعرض الناجح والفاشل ولا تترك الواجهة بحالة كاذبة.
