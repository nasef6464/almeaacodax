## القرار والنطاق

نفّذ المالك تفويضًا صريحًا للكتابة في الإنتاج ببيانات اصطناعية معزولة فقط. استُخدمت
مدرسة قائمة مع فصلين جديدين، معلمين جديدين، ومستخدمين تجريبيين فقط؛ لم يُستخدم
طالب أو معلم حقيقي. جميع الأسرار وPINs بقيت خارج Git وهذا التقرير.

## ما نُفذ وثبت

| البند | الدليل | النتيجة |
|---|---|---|
| فصلان ومعلمان | جلستا معلم منفصلتان، كل واحدة من سؤالين معتمدين | PASS |
| عزل الفصل | طالب الفصل B حاول PIN الخاص بالفصل A | `403` كما هو مطلوب |
| إجابة وتكامل الكتابة | إجابة مكررة أعادت `responseId` نفسه؛ التقرير النهائي حفظ استجابة واحدة | PASS |
| سلامة العرض | إسقاط سؤال الطالب لا يحمل `correctOptionIndex` | PASS |
| Socket / شبكة ضعيفة | قطع transport متعمد ثم reconnect وroom rejoin مع delay مضبوط 800ms | PASS؛ recovery `2950ms` |
| Reports / Intelligence | المشرف التجريبي قرأ التقرير وذكاء المدرسة داخل نطاقه | PASS |
| Intervention | تدخل لمسار قائم على evidence قبلية، ثم جلسة متابعة | `measured`؛ baseline evidence = 1، follow-up evidence = 1 |

## القياسات الخام المختصرة

- نافذة القياس: جلسات Pilot الاصطناعية في 2026-09-10.
- Join: `n=1`, `1159ms` (p50/p95 للعينة نفسها).
- Answer write: `n=1`, `1806ms` (p50/p95 للعينة نفسها).
- Reconnect: محاولة موثقة واحدة، recovered `1/1`، زمن `2950ms`.
- التزامن المرصود: طالبان مصرحان في جلستين منفصلتين، أي `2` مشاركين حيّين عبر
  فصلين؛ كل فصل احتوى مشاركًا حيًا واحدًا في هذه التجربة.
- التقارير: جلسات الـPilot المنتهية ظاهرة للمشرف؛ وتمت قراءة intervention outcome
  بحالة `measured`.

هذه أرقام ملاحظة Pilot صغيرة، وليست benchmark لقدرة production أو SLA.

## القرار التجاري

**GO للـPilot التجاري المحدود:** يمكن عرض Smart Classroom لمدرسة محددة بعقد يحتوي
`SMART_CLASSROOM` و`SCHOOL_INTELLIGENCE` و`INTERVENTION_CENTER`، مع تشغيل أولي
محافظ لا يتجاوز **فصلين متزامنين ومشاركًا حيًا واحدًا لكل فصل** إلى أن ينفذ قياس
تزامن أكبر مفوض صراحةً. لا يُذكر حد مقاعد أكبر أو SLA في العقد اعتمادًا على هذه
العينة وحدها.

## غير مثبت / مؤجل

- الأداء مع أكثر من مشارك حي واحد في الفصل، أو أكثر من فصلين متزامنين.
- اتصال ضعيف حقيقي (throttling/packet loss من شبكة جهاز)؛ المثبت هو قطع transport
  ثم عودة محكومة فقط.
- Pilot بمدرستين منفصلتين في الإنتاج؛ منع cross-school مثبت بعقد CI، أما الـPilot
  الحي فاختبر عزل فصلين داخل المدرسة نفسها.
- حذف بيانات الـPilot تلقائيًا. لا يوجد مسار API آمن لحذف session/response/
  intervention دون ترك آثار غير مترابطة، لذلك حُفظت السجلات الاصطناعية كأثر تدقيق
  محدود بدل تنفيذ حذف واسع أو مباشر في قاعدة البيانات.

## القرار التالي

إذا طلبت المدرسة أكثر من الحد المحافظ أعلاه، نفّذ Pilot قياس منفصل بعدد طلاب وفصول
محدد، ثم فقط يتم اعتماد حد تجاري أعلى. لا يلزم بناء Video/WebRTC أو microservices
أو rollups لهذه الخطوة.
