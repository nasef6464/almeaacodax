# ALMEAA Question Bank V2 — عقد إعادة الإدخال والذكاء الاصطناعي

**الحالة:** عقد تنفيذي لإعادة بناء بنك أسئلة القدرات الكمي قبل وجود بيانات طلاب حقيقية.

## 1) الهدف

إعادة إدخال أسئلة كتابي القدرات الكمي بصورة نظيفة وقابلة للتعديل، مع الحفاظ على تجربة الطالب البصرية من الصورة الأصلية، وفي الوقت نفسه توفير سياق نصي/رياضي/صوتي منظم للذكاء الاصطناعي.

مصدر العرض للطالب:
- صورة السؤال المقصوصة عالية الجودة على R2.
- نص السؤال عند الحاجة.
- أزرار الإجابة. إذا كانت قيم الاختيارات مطبوعة داخل الصورة يمكن أن تكون أزرار الطالب فقط: أ، ب، ج، د.

مصدر الفهم للمنصة:
- text
- aiContext
- skillIds
- correctOptionIndex
- explanation / hint / solvingStrategy
- videoUrl

لا تُخزن صور Base64 داخل MongoDB.

## 2) الهوية الثابتة لكل سؤال

لكل سؤال هويتان:

1. `id`: معرف داخلي دائم. الخادم ينشئه تلقائيًا إذا لم يرسله المستورد.
2. `questionCode`: كود بشري ثابت وفريد يستخدم في PowerPoint، Excel، البحث، ربط فيديو YouTube، والباركود/QR لاحقًا.

للاستيراد من الكتب الحالية يفضّل الكود الحتمي:

`QDR-QNT-{DOCUMENT_CODE}-P{PAGE_3}-Q{QUESTION_2}`

أمثلة:
- `QDR-QNT-FND26-P015-Q01`
- `QDR-QNT-COL2627-P020-Q14`

إذا كانت الصفحة تحتوي سؤالًا بلا رقم واضح، استخدم:
`QDR-QNT-{DOCUMENT_CODE}-P{PAGE_3}-C{CROP_2}`

لا تغيّر `questionCode` بعد نشر السؤال وربطه بمواد شرح. تغيير النص أو الصورة أو الإجابة لا يغيّر الكود.

أكواد المصدر المقترحة:
- `FND26`: كتاب التأسيس الكمي.
- `COL2627`: كتاب التجميعات 2026–2027.

## 3) مسار الصورة

استخدم R2 بمسار versioned، مثل:

`questions/v2/qudrat/quant/FND26/p015/QDR-QNT-FND26-P015-Q01-v1.webp`

عند استبدال الصورة:
- ارفع نسخة جديدة `v2`, `v3`...
- حدّث `imageUrl` فقط بعد نجاح الرفع.
- لا تستبدل الملف القديم في مكانه أثناء مرحلة المراجعة.

## 4) عقد Question V2

الحقول الأساسية:

```ts
{
  id,
  questionCode,
  text,
  imageUrl,
  imageAlt,
  options,
  optionsEmbeddedInImage,
  correctOptionIndex,
  explanation,
  hint,
  solvingStrategy,
  videoUrl,
  pathId,
  subject,
  sectionId,
  skillIds,
  difficulty,
  type,
  examType,
  source,
  year,
  aiContext,
  sourceMeta
}
```

### aiContext

```ts
{
  readableText: string,
  speechText: string,
  visualDescription: string,
  optionTexts: string[],
  mathExpressions: [
    {
      latex: string,
      spokenArabic: string
    }
  ],
  concepts: string[],
  requiredData: string[],
  version: 1
}
```

قواعد إلزامية:
- `readableText`: السؤال كاملًا دون الحل أو الإجابة الصحيحة.
- `speechText`: صياغة عربية طبيعية للنطق، لا قراءة LaTeX حرفيًا.
- `visualDescription`: وصف الرسم/الجدول/الأبعاد الضرورية فقط دون حل.
- `optionTexts`: القيم الحقيقية للاختيارات عندما تظهر القيم داخل الصورة وتكون `options=["أ","ب","ج","د"]`.
- `mathExpressions`: الصيغ الرياضية المعيارية مع نطقها العربي.
- لا تضع `correctOptionIndex` أو الحل داخل `aiContext`.

### sourceMeta

```ts
{
  documentCode,
  documentTitle,
  page,
  questionNumber,
  cropIndex,
  importBatchId,
  imageVersion,
  imageHash
}
```

## 5) الاختيارات داخل الصورة

إذا كانت قيم أ/ب/ج/د واضحة داخل الصورة:

```ts
options = ["أ", "ب", "ج", "د"]
optionsEmbeddedInImage = true
aiContext.optionTexts = [
  "القيمة الفعلية للاختيار أ",
  "القيمة الفعلية للاختيار ب",
  "القيمة الفعلية للاختيار ج",
  "القيمة الفعلية للاختيار د"
]
```

يجب أن يكون عدد `aiContext.optionTexts` مساويًا لعدد `options`. الخادم يرفض عدم التطابق.

إذا لم تكن قيم الاختيارات داخل الصورة، خزّن نصوص الاختيارات نفسها في `options` واجعل `optionsEmbeddedInImage=false`.

## 6) الرياضيات واتجاه RTL

الصورة هي مصدر العرض الأساسي لهذه الكتب. لا تعِد بناء شكل السؤال بصريًا إذا كانت الصورة أوضح.

لكن استخرج كل تعبير رياضي ضروري إلى `mathExpressions`.

أمثلة:
- `7^2` → `{"latex":"7^2","spokenArabic":"سبعة أس اثنين"}`
- `\\sqrt{49}` → `{"latex":"\\sqrt{49}","spokenArabic":"الجذر التربيعي لتسعة وأربعين"}`
- `\\frac{3}{5}` → `{"latex":"\\frac{3}{5}","spokenArabic":"ثلاثة على خمسة"}`
- `|-4|` → النطق: `القيمة المطلقة لسالب أربعة`.

لا تعتمد على ترتيب النص المستخرج من PDF وحده عند الأسس والجذور والكسور. الصورة المرئية هي مرجع الحقيقة.

## 7) المهارات: ممنوع إنشاء مهارات جديدة أثناء الاستيراد

المسار:
- `p_1777779639431` — القدرات العامة

المادة:
- `sub_1777779748206` — القسم الكمي

Gemini/Antigravity يجب أن يختار فقط من الـ taxonomy الموجودة حاليًا. لا ينشئ Section أو Skill أو SubSkill جديدًا.

لكل سؤال كمي خزّن عادة:
`skillIds = [MAIN_SKILL_ID, SUB_SKILL_ID]`

## 8) قاعدة التصنيف

1. استخدم عنوان الدرس/القسم في المصدر لتحديد Main Skill المرشح.
2. اقرأ السؤال نفسه لتحديد SubSkill.
3. تحقق أن SubSkill المختارة موجودة تحت نفس Main Skill في القائمة أعلاه.
4. لا تنشئ مهارة جديدة إذا لم تجد تطابقًا.
5. عند الشك: `needs_review=true` ولا تعتمد السؤال.
6. لا تستخدم مهارة عامة لمجرد أن السؤال يقع في نفس الصفحة إذا كانت فكرة السؤال تخص SubSkill أخرى واضحة.
7. السؤال متعدد المهارات يمكن أن يحمل أكثر من SubSkill فقط عند الضرورة، لكن يجب أن يكون أول زوج هو المهارة الأساسية.

## 9) التحقق من الإجابة

- استخرج الإجابة من السؤال/مفتاح الإجابات في المصدر.
- قارنها مع الحل الموجود في الكتاب إن وجد.
- لا تعتمد سؤالًا إذا اختلفت نتيجة الحساب مع مفتاح المصدر.
- لا تجعل Gemini "يصحح الكتاب" تلقائيًا. الاختلاف يذهب للمراجعة البشرية مع تقرير واضح.
- `correctOptionIndex` يظل صفر-مبنيًا: أ=0، ب=1، ج=2، د=3.

## 10) دورة المراجعة

كل سؤال يمر بـ:

`extract → crop → classify → AI context → answer validation → draft → review → approved`

ابدأ بعينة 40 سؤالًا تغطي:
- عمليات
- كسور
- أسس
- جذور
- جداول مقارنة
- رسومات هندسية

لا تبدأ Full Import قبل نجاح العينة بصريًا وبيانيًا.

## 11) ربط الفيديو والـ PowerPoint

`questionCode` هو مفتاح الربط الخارجي.

أي ملف فيديو/Excel/PowerPoint مستقبلي يستخدم:

```csv
questionCode,videoUrl
QDR-QNT-FND26-P015-Q01,https://youtube.com/...
QDR-QNT-COL2627-P020-Q14,https://youtube.com/...
```

لا تعتمد على رقم الصف في Excel ولا على اسم الصورة وحده.

يوجد endpoint إداري دفعي لربط الفيديوهات بالكود دون لمس بقية السؤال:

`PATCH /api/quizzes/questions/video-links`

Body:

```json
{
  "items": [
    {"questionCode":"QDR-QNT-FND26-P015-Q01","videoUrl":"https://youtube.com/..."}
  ]
}
```

يمكن إرسال حتى 500 رابط في الدفعة الواحدة. يعيد الخادم الأكواد المفقودة بدل إنشاء أسئلة جديدة.

عند تصدير الشرائح:
- ضع `questionCode` ظاهرًا بخط صغير في الشريحة.
- يمكن توليد QR من نفس الكود أو من رابط السؤال/الفيديو عندما نعتمد route عامة لذلك.
- أي تحديث للصورة أو النص أو الإجابة يبقى مرتبطًا بنفس `questionCode`.

## 12) التحرير من مركز الأسئلة

يجب أن يستطيع الإداري عند فتح سؤال موجود:
- رؤية الصورة الأساسية الحالية.
- استبدال الصورة أو حذفها.
- تعديل نص السؤال.
- تعديل الاختيارات والإجابة الصحيحة.
- رؤية/تغيير المهارات المرتبطة من taxonomy الحالية فقط.
- تعديل رابط فيديو الشرح.
- تعديل aiContext النصي عند الحاجة.
- حفظ التعديل على نفس السؤال ونفس `questionCode`.

## 13) حماية AI

في العرض العادي للطالب لا يُرسل:
- correctOptionIndex
- explanation
- hint
- solvingStrategy
- aiContext الداخلي
- sourceMeta

أثناء المساعدة قبل التسليم يستخدم خادم المعلم:
- readableText
- speechText
- visualDescription
- optionTexts
- mathExpressions
- skill labels
- hint آمن إن سمحت سياسة الجلسة

بعد التسليم/المراجعة فقط يمكن إضافة:
- correctOptionIndex
- explanation
- solvingStrategy

## 14) إعادة البناء والتنظيف

الحذف الشامل للأسئلة/الاختبارات القديمة ليس جزءًا من هذا العقد البرمجي.

الترتيب:
1. دمج Question V2.
2. استيراد Pilot.
3. إثبات نجاح التحرير والمهارات والذكاء الاصطناعي.
4. أخذ Snapshot/manifest للقديم.
5. بعد موافقة المالك الصريحة: حذف الأسئلة/الاختبارات التجريبية المستهدفة فقط.
6. Full Import من الكتابين.
7. تحقق counts + skill coverage + image coverage + answer validation + AI readiness.
