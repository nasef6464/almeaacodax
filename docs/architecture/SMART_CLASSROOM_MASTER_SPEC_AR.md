## 1. الرؤية والهدف الاستراتيجي (Product Vision)

تحويل منصة المئة (ALMEAA) من مجرد منصة تعليمية لبيع الدورات للأفراد (B2C) إلى **نظام تشغيل تعليمي مدرسي متكامل قابل للترخيص السنوي (B2B School Learning Operations System)**.

### الركائز الجوهرية للرؤية:
1. **الفصل الذكي التفاعلي (Smart Classroom):** تحويل الحصة الدراسية إلى تجربة تفاعلية حية تضاهي (Kahoot + Nearpod) ولكنها مبنية ومغذّاة مباشرة من بنك أسئلة قياس والقدرات والتحصيلي المعتمد في المنصة.
2. **التحضير الذكي اللحظي للحضور والغياب (Smart Attendance & Absence):** رصد الحضور تلقائياً بمجرد دخول الطالب الحصة بحسابه عبر PIN أو QR ومطابقته فوراً مع القائمة الرسمية للفصل، مع رصد الغائبين والمتأخرين.
3. **السجل التراكمي والتقييم الأسبوعي والشهري (Longitudinal Performance Tracking):** حفظ كل حصة وسؤال في سجل تراكمي دائم يمكن المعلم ومدير المدرسة من قياس تطور الطالب فصلياً وأسبوعياً وشهرياً واكتشاف فجوات التحصيل.
4. **محرك حصص الدعم والتقوية الآلي (Smart Remedial & Live Tutoring Bridge):** الربط المباشر بين المهارات التي يضعف فيها الطلاب في الحصص وبين إطلاق وجدولة حصص تقوية ودعم مباشر بضغطة زر واحدة تضم الطلاب المستهدفين.
5. **مركزية اتخاذ القرار للمشرف والمدير (Centralized Supervisor & Principal Cockpit):** فصل صلاحيات المعلم (المحصورة في فصوله ومواده) عن المشرف والمدير الذي يمتلك قمرة قيادة مركزية لمقارنة كافة فصول المدرسة والمعلمين واكتشاف المهارات الحرجة وتوجيه الدعم.
6. **الحفاظ الصارم على لوحة المشرف (`SupervisorDashboard`):** الحفاظ على كافة إمكانيات المشرف الحالية وتوسيعها بإضافات هادئة دون تعقيد أو تغيير لما اعتاد عليه.
7. **الحساب الموحد متعدد السياقات (Single Account / Multi-Context):** الطالب له حساب واحد فقط؛ يدخل به كمتعلم حر في المنصة وكطالب رسمي في مدرسته.
8. **التحليل ثنائي المصدر (Dual-Source Analytics):** فصل نتائج وتقييمات المدرسة الرسمية عن نشاط الطالب وتدريباته الفردية الحرة، مع إمكانية المقارنة الذكية بينهما.
9. **البيع الموديولي بالعقود (B2B Modular Licensing):** إمكانية تخصيص وتفعيل الباقات لكل مدرسة بحسب عقدها (مسارات، فصول ذكية، بنوك أسئلة، حصص تقوية).

## 3. المعمار الهندسي وقواعد البيانات (Data Architecture)

لحماية النظام الحالي وعدم إحداث أي خلل في المستخدمين أو الاختبارات القائمة، تعتمد الإضافات على نماذج جديدة متوافقة (Non-breaking & Additive):

### 1. جدول العضوية المدرسية (`SchoolMembership`)
يربط حساب الطالب الموحد بمدرسته وفصله دون الحاجة لإنشاء حساب ثانٍ:
```typescript
interface SchoolMembership {
  id: string;
  userId: string;              // معرف الحساب الموحد
  schoolId: string;            // معرف المدرسة
  classId: string;             // معرف الفصل (Group: CLASS)
  role: 'student' | 'teacher' | 'supervisor';
  status: 'active' | 'suspended' | 'graduated';
  academicYear: string;        // مثلاً 2026-2027
  createdAt: Date;
  updatedAt: Date;
}
```

### 2. جدول العقد والخدمات المدرسية (`SchoolContract`)
المسؤول عن فتح أو إغلاق الخصائص لكل مدرسة من الخادم:
```typescript
interface SchoolContract {
  id: string;
  schoolId: string;
  contractNumber: string;
  status: 'active' | 'expired' | 'pending';
  startsAt: Date;
  endsAt: Date;
  modules: {
    smartClassroom: boolean;       // تفعيل الفصول الذكية
    pathsAndCourses: string[];     // المسارات المفتوحة (قدرات، تحصيلي..)
    questionBankAccess: boolean;   // صلاحية استعراض بنك الأسئلة
    liveTutoring: boolean;         // حصص الدعم والتقوية المباشرة
    dualAnalytics: boolean;        // تقارير المقارنة المزدوجة
    customBranding: boolean;       // هوية وشعار المدرسة
  };
  limits: {
    studentSeats: number;          // سعة مقاعد الطلاب
    teacherSeats: number;          // سعة المعلمين
    concurrentSessions: number;    // أقصى عدد فصول ذكية متزامنة
  };
}
```

### 3. جدول جلسة الفصل الذكي (`ClassroomSession`)
سجل الحصة التفاعلية المباشرة:
```typescript
interface ClassroomSession {
  id: string;
  schoolId: string;
  classId: string;
  teacherId: string;
  subjectId: string;
  skillIds: string[];
  title: string;
  pinCode: string;                 // رمز دخول 6 أرقام
  status: 'lobby' | 'live' | 'completed' | 'cancelled';
  totalRosterCount: number;        // عدد طلاب الفصل المسجلين رسمياً
  presentCount: number;            // عدد الحاضرين
  absentCount: number;             // عدد الغائبين
  questionSnapshots: Array<{       // لقطة ثابتة من الأسئلة لحماية النزاهة
    questionId: string;
    text: string;
    options: string[];
    correctIndex: number;
    explanation?: string;
    timeLimitSeconds: number;
  }>;
  currentQuestionIndex: number;
  currentQuestionStartedAt?: Date;
  startedAt?: Date;
  endedAt?: Date;
}
```

### 4. جدول الحضور والغياب في الحصة الذكية (`ClassroomAttendance`)
تسجيل دقيق للحضور والغياب مع ربطه بقائمة طلاب الفصل الرسمية:
```typescript
interface ClassroomAttendance {
  id: string;

  schoolId: string;
  classId: string;

  teacherNotes?: string;
}
```

### 5. جدول إجابات الطلاب اللحظية (`ClassroomResponse`)
```typescript
interface ClassroomResponse {
```

### 6. جدول السجل التراكمي للمهارات أسبوعياً وشهرياً (`StudentSkillMasteryRollup`)
محرك تحليل نقاط القوة والضعف المستمرة:
```typescript
interface StudentSkillMasteryRollup {

```

### 7. جدول حصص الدعم والتقوية المباشرة (`RemedialSupportSession`)
محرك الربط بين الضعف المكتشف وجدولة الدعم:
```typescript
interface RemedialSupportSession {
  id: string;
  schoolId: string;
  subjectId: string;
  skillId: string;
  skillName: string;
  teacherId: string;
  title: string;                   // مثلاً: حصة دعم مهارة: المتتابعات الهندسية
  scheduledAt: Date;
  durationMinutes: number;
  meetingProvider: 'zoom' | 'teams' | 'google_meet' | 'internal';
  meetingUrl: string;
  targetStudentIds: string[];      // الطلاب الذين رُصد لديهم ضعف (<60%)
  attendedStudentIds: string[];
  status: 'scheduled' | 'live' | 'completed' | 'cancelled';
  sourceSessionIds: string[];      // الحصص التي تم اكتشاف الضعف فيها
  notes?: string;

```

### 8. سياق النتيجة في (`QuizResult.learningContext`)
حفظ مصدر النتيجة لضمان الفصل التام بين أداء المدرسة وأداء المنصة:
```typescript
learningContext?: {
  source: 'school_assessment' | 'smart_classroom' | 'platform_self_study' | 'remedial_session';
  schoolId?: string;
  classId?: string;
  teacherId?: string;
  sessionId?: string;
}
```

## 4. نظام الحضور والغياب التلقائي (Smart Attendance Engine)

### آلية العمل الذكية في الفصل:
1. **تزامن القائمة الرسمية (Roster Sync):** عند بدء المعلم الحصة لفصل (مثلاً 2/أ)، يستدعي النظام فوراً جميع الطلاب المقيدين في هذا الفصل من جدول `SchoolMembership`.
2. **التحضير التلقائي الفوري (Zero-Click Check-in):**
   - بمجرد دخول الطالب عبر الـ PIN أو مسح الـ QR Code، يتحقق النظام من هويته وتتحول حالته فوراً إلى `حاضر` (Present).
   - إذا دخل الطالب بعد أن أطلق المعلم السؤال الأول، تُسجل حالته تلقائياً `متأخر` (Late).
3. **رصد المتغيبين فوراً (Instant Absence Roster):**
   - تظهر للمعلم قائمة واضحة: من حضر، ومن لم ينضم بعد.
   - يمكن للمعلم بضغطة زر تحويل أي طالب إلى `معذور` (Excused) في حال غياب بعذر أو وجود عطل فني.
4. **التكامل مع السجل المدرسي العام:**
   - تقرير الحضور والغياب يُحفظ مع الجلسة كوثيقة رسمية للمدرسة.
   - يدخل معدل الحضور في التقرير الأسبوعي والشهري للطالب والفصل على مستوى المدرسة.

## 5. السجل التراكمي ومحرك حصص الدعم والتقوية (Longitudinal Analytics & Remedial Bridge)

### أ. التقييم التراكمي (أسبوعي / شهري):
- لا تضيع إجابات الطلاب في الحصة الذكية؛ بل تتراكم تلقائياً في `StudentSkillMasteryRollup`.
- **مؤشر الخطر الأكاديمي:** إذا انخفضت نسبة إتقان الطالب في مهارة معينة عن **60%** خلال حصتين أو أكثر في الشهر، يُصنف الطالب تلقائياً ضمن فئة `بحاجة لدعم عاجل` (Needs Remediation).
- يمكن للمعلم أو المشرف استعراض **"خريطة المهارات الحرجة"** للفصل، والتي توضح المهارات التي يشترك فيها عدد كبير من الطلاب في الضعف.

### ب. محرك جدولة حصص الدعم والتقوية (1-Click Remedial Bridge):
1. عند ظهور تقرير الحصة أو التقرير الشهري وتحديد مهارة ضعيفة (مثل: "الأنماط العددية")، يظهر زر إجراء مباشر:
   **`[جدولة حصة دعم مباشر لهذه المهارة 🎯]`**
2. عند الضغط عليه، تنبثق نافذة إنشاء حصة تقوية تلقائية:
   - العنوان واسم المهارة محددين آلياً.
   - قائمة الطلاب الضعفاء في هذه المهارة مضافة ومحددة مسبقاً (Pre-populated).
   - إدخال وقت الحصة ورابط البث (Teams / Zoom).
3. فور الحفظ، يرسل النظام إشعاراً فورياً على لوحة الطلاب المعنيين:
   *"تمت جدولتك في حصة تقوية ودعم في مهارة (الأنماط العددية) يوم الثلاثاء الساعة 5:00 عصراً"*.

## 6. مستويات الصلاحية ومركزية اتخاذ القرار (Role Hierarchy & Decision Cockpit)

### أ. حساب المعلم (Teacher Scope) — المستوى التنفيذي في الفصل:
- **نطاق الوصول:** محصور حصراً في الفصول والمواد المسندة للمعلم في جدول التكليفات (`TeachingAssignment`).
- **الإمكانيات:**
  - بدء حصة ذكية جديدة واختيار الأسئلة من بنك المنصة.
  - التحكم في مسار الحصة بالبروجكتور وتلقي الإجابات.
  - اعتماد الحضور والغياب اليدوي للحصة.
  - استعراض تقارير حصصه وفصوله التراكمية الأسبوعية والشهرية.
  - جدولة حصص تقوية لطلابه الضعفاء.

### ب. حساب المشرف ومدير المدرسة (Supervisor / Principal Scope) — مركزية اتخاذ القرار:
- **نطاق الوصول:** المدرسة كاملة بكافة فصولها ومراحلها ومعلميها.
- **قمرة القيادة المركزية (Centralized Decision Cockpit):**
  1. **المقارنة التنافسية بين الفصول:** مقارنة مستوى فصل (2/أ) بفصل (2/ب) في نفس المادة، ومعرفة الفروق في نسب الإتقان وسرعات الحل.
  2. **متابعة نشاط المعلمين:** جدول يوضح عدد الحصص الذكية المنفذة بواسطة كل معلم، ونسب حضور طلابه، ومعدل الاستجابة.
  3. **خريطة المهارات الحرجة للمدرسة (School-wide Skill Heatmap):** عرض أكثر 5 مهارات يعاني منها طلاب المدرسة ككل، لاتخاذ قرارات على مستوى الإدارة (مثل: تخصيص أسبوع لتقوية مهارات الهندسة أو الإحصاء).
  4. **مؤشرات الحضور والانضباط المدرسي:** سجل تراكمي لنسب الحضور والغياب في الحصص الذكية مجمعاً أسبوعياً وشهرياً.
  5. **التصدير التنفيذي الرسمي:** تنزيل تقارير شاملة بضغطة زر بصيغة PDF تتضمن شعار المدرسة، جاهزة للعرض على إدارة التعليم أو مالك المدرسة.

## 7. التصور التصميمي للواجهات (UI/UX Blueprint)

### أ. شاشة المعلم (Teacher Control Console)
- شاشة إدارية هادئة بلون رمادي داكن ونغمات كحلية حديثة (`Slate-900 / Indigo`).
- **درج التحضير اللحظي (Attendance Tray):** شريط علوي صغير يُظهر حالة الحضور (أخضر: حاضر، أصفر: متأخر، رمادي: غائب) مع إمكانية تعديل سريعة بنقرة واحدة.
- **عناصر التحكم بالحصة:** زر تشغيل السؤال الكبير مع مؤشر بصري دائري للوقت المتبقي، وشريط العداد المباشر لعدد المجيبين، ومفتاح تبديل "إخفاء أسماء الطلاب في شاشة البروجكتور".

### ب. شاشة العرض بالبروجكتور (Smart Board / Projector Display)
- مساحة سينمائية واسعة وعالية التباين، مخصصة للمشاهدة من مسافة 5–10 أمتار داخل الفصل.
- **في وضع الانتظار (Lobby):** كود الـ PIN كبير جداً في المنتصف مع رمز الـ QR بدقة فائقة، وصور رمزية حية للطلاب المنضمين تتصاعد بأسلوب سلس ومشجع.
- **أثناء السؤال:** نص السؤال وخياراته بخط عريض بألوان متباينة مع شريط تقدم زمني منساب.
- **بعد السؤال:** أعمدة بيانية لتوزيع اختيارات الفصل (أ، ب، ج، د) وتمييز الإجابة الصحيحة بالأخضر الزمردي وشرح طريقة الحل.

### ج. شاشة الطالب في الجوال (Student Mobile Controller)
- واجهة تطبيق ويب تفاعلية مريحة للمس وسريعة الاستجابة للغاية (`Touch-first / Instant Feedback`).
- أزرار خيارات عريضة وواضحة (أ، ب، ج، د) بألوان هادئة وسهلة الضغط.
- وميض تأكيد هادئ فور اختيار الإجابة، مع نتيجة فورية وشرح بمجرد إغلاق السؤال.

### د. لوحة المشرف المطورة (`SupervisorDashboard`)
- **المحافظة التامة:** بقاء الهيكل الحالي (7 تبويبات) كما هو تماماً.
- **قمرة القيادة المركزية:**
  - بطاقة **"حصص اليوم والحضور"**: عدد الحصص المنعقدة اليوم في المدرسة ونسبة الحضور العامة.
  - تبويب **"السجل التراكمي وحصص الدعم"**:
    - فلترة حسب: [الفصل] - [المادة] - [الأسبوع / الشهر].
    - قائمة الطلاب الأكثر احتياجاً للدعم الأكاديمي مع زر مباشر `[جدولة حصة دعم]`.
    - زر مقارنة الفصول: عرض رسم بياني للمقارنة بين شعب الصف الثاني ثانوي.
  - تبويب **"التحليل ثنائي المصدر (Dual Analytics)"**:
    - مقارنة أداء المدرسة الرسمي بحصصها واختباراتها مقابل نشاط الطلاب الفردي الذاتي على منصة المئة.

## 9. ضوابط الأمان والاستقرار والـ Realtime

1. **عزل المدارس المطلق (Multi-School Isolation):**
   - حظر تام على الخادم لأي انضمام إلى غرفة سوكت (`Socket Room`) لا يتبع لمدرسة وفصل الطالب.
   - التحقق من التوقيع والمصادقة في كل عملية تسليم إجابة (`Session Handshake Auth`).
2. **منع تسريب الإجابات للطلاب (No Client-side Leakage):**
   - السؤال يُرسل لجوال الطالب بدون حقل الإجابة الصحيحة.
   - التصحيح يتم بنسبة 100% على الخادم (Server-side Evaluation).
3. **موثوقية الاتصال ومقاومة انقطاع الإنترنت (Network Resilience & Idempotency):**
   - كل إجابة تحمل `idempotencyKey` لمنع تكرار الإجابة عند ضعف الاتصال.
   - إذا انقطع اتصال الطالب ثم عاد، يستعيد السؤال الحالي فوراً بحسب زمن الجلسة الجارية.
4. **تكامل الحصص المباشرة الآمن (Live Tutoring Bridge):**
   - الاعتماد على روابط الاجتماعات الخارجية المشفرة (Zoom / Microsoft Teams / Google Meet) المدمجة داخل جدول المنصة، بدلاً من تكليف خوادم المنصة ببث الفيديو الثقيل.

## 10. خارطة طريق التنفيذ لكودكس (Implementation Roadmap for Codex)

### المرحلة 0: الأساس الأمني وقواعد العزل (`Security & Boundary Baseline`)
- تدقيق وتأمين غرف الـ Sockets الحالية لتقبل المصادقة والتحقق من رقم المدرسة والفصل.
- حماية مسارات الباركود والاختبارات الحية لتكون محكومة بملكية المدرسة والمعلم.

### المرحلة 1: العضوية المدرسية وتعدد السياقات (`SchoolMembership & Single Account`)
- إنشاء نموذج `SchoolMembership`.
- دعم محول الحساب في واجهة الطالب (بين حساب المدرسة والحساب الشخصي) دون تكرار الحسابات.

### المرحلة 2: محرك العقود والخدمات (`SchoolContract & Admin Modules`)
- بناء نموذج `SchoolContract` في الخادم.
- إضافة واجهة التحكم في باقات وعقود المدارس داخل شاشة إدارة المدارس للمدير (`Admin`).

### المرحلة 3: شريحة الفصل الذكي ونظام الحضور (`Smart Classroom & Attendance Vertical Slice`)
- شاشة المعلم لبدء الحصة واختيار الأسئلة من بنك المنصة، مع درج تحضير الطلاب اللحظي.
- شاشة البروجكتور (عرض الـ PIN والـ QR Code ونسب الإجابات المباشرة).
- شاشة جوال الطالب للاستجابة اللحظية ورصد الحضور تلقائياً بمجرد الدخول.

### المرحلة 4: السجل التراكمي وقمرة قيادة المشرف (`Longitudinal Analytics & Supervisor Cockpit`)
- تجميع إجابات الحصص في سجل تراكمي أسبوعي وشهري (`StudentSkillMasteryRollup`).
- تطوير لوحة المشرف لإضافة بطاقة الفصول الذكية، ومقارنة الفصول، وخريطة المهارات الحرجة للمدرسة.
- تفعيل محرك حصص الدعم والتقوية بزر بضغطة واحدة (`Remedial Support Bridge`).
- توليد وطباعة تقارير الحصص والحضور والغياب بصيغة PDF أنيقة.

### المرحلة 5: التجربة الميدانية المعتمدة (`Controlled School Pilot`)
- تشغيل حصة تجريبية متكاملة في مدرسة حقيقية بمشاركة معلمين وطلاب في بيئة مصرح بها، لتوثيق الجاهزية والبدء في البيع التجاري الواسع.
