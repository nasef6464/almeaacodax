- المشرف: الإنشاء أو الربط بالمدرسة/الفصل موجود.
- المعلم: العضوية والتكليف بالمادة والفصل موجودان.

- النقص الحالي: العمليات متفرقة ولا تبدأ كلها من مدخل واحد واضح داخل
  `People Hub`، والتحقق بإعادة القراءة من السيرفر ليس موحدًا بعد كل عملية.

## نتيجة التنفيذ الحالية

- أضيف مدخل واحد: **إضافة أو ربط مستخدم**، ويقود إلى مدير المدرسة أو المشرف أو

## PH1 — مدخل موحد للمستخدمين

- إضافة زر واضح داخل `SchoolPeopleHubTab`: **إضافة أو ربط مستخدم**.
- الأنواع: مدير مدرسة، مشرف، معلم مدرسة، طالب، ولي أمر.
- كل اختيار يعيد استخدام الواجهة أو التدفق الموجود بالفعل.
- لا Backend جديد ولا نظام Users جديد ما دامت الخدمات الحالية تكفي.

### بوابة الإغلاق

كل نوع مستخدم يبدأ الإجراء الصحيح من `People Hub`، ولا يفتح تدفقًا خاصًا بدور
آخر.

## PH2 — ربط العلاقات والصلاحيات

- المدير ← المدرسة وصلاحياته عبر `SchoolDirectorDelegationPanel`.
- المشرف ← المدرسة أو الفصل عبر `SchoolQuickSupervisorCard`.
- المعلم ← عضوية المدرسة ثم المادة والفصل عبر `TeachingAssignmentPanel`.
- الطالب ← المدرسة والفصل عبر التدفق الحالي.
- ولي الأمر ← الطالب/الطلاب عبر `linkedStudentIds` أو العلاقات الحالية.
- بعد أي mutation: إعادة قراءة البيانات من السيرفر، مع حالات تحميل ونجاح وفشل.
- تصحيح أي تسمية تخلط بين مدير المدرسة والمشرف.
- الحفاظ على RBAC والعقود العامة للـAPI والبيانات كما هي.

### بوابة الإغلاق

العلاقة التي تظهر في الواجهة تكون محفوظة ومقروءة من السيرفر، مع منع الربط خارج
نطاق المدرسة أو الفصل المسموح.
