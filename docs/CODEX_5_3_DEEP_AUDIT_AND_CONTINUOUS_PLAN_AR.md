# فحص عميق وخطة عمل مستمرة مناسبة لـ Codex 5.3

التاريخ: 2026-05-20
المشروع: ALMEAA CODAX / منصة المئة
النطاق: لوحة المدير، التسجيل، واتساب، المساعد الذكي، تنظيف المشروع، الفحص التشغيلي، وربط التطوير بعد النقل لاستضافة واحدة.

## 1. ملخص الحالة الحالية

- الإنتاج يعمل: `/api/health` يرجع `200` و `ready=true` وقاعدة البيانات متصلة.
- المساعد الذكي موجود برمجيًا في السيرفر والواجهة، لكنه يعمل حاليًا على وضع `local-fallback` فقط ولا يوجد مزود AI خارجي مفعّل.
- لوحة المدير تحتوي تبويبات كثيرة وشغالة جزئيًا، لكن هناك شاشات ما زالت تفترض وجود `user.token` رغم أن النظام انتقل إلى Cookie Auth.
- تسجيل الدخول بالإيميل/الباسورد يحتاج تشخيص عملي بحساب معروف، لأن الاعتمادات المحلية الحالية لا تحتوي `ADMIN_EMAIL/ADMIN_PASSWORD` بأسماء مباشرة.
- تسجيل واتساب غير مكتمل كـ Auth حقيقي: الموجود الآن إعداد مزود واتساب/إشعارات/اختبار إرسال، وليس مسار OTP لتسجيل الدخول.
- توجد تعديلات محلية غير مرفوعة وملفات تقارير/نتائج اختبار كثيرة تحتاج تصنيف قبل التنظيف أو الحذف.

## 2. نتائج الفحص المهمة

### 2.1 لوحة المدير

الموجود:
- تبويب إدارة المستخدمين.
- تبويب إدارة المسارات والدورات والتأسيس والتدريب والاختبارات والمكتبة.
- تبويب الصفحة الرئيسية.
- تبويب الخطوط.
- تبويب التكاملات والتسجيل.
- تبويب المساعد الذكي.
- تبويب المالية والمدارس والإشعارات والتقارير.

المخاطر:
- `HomepageManager.tsx` يشترط `user.token` قبل الحفظ، وهذا قد يفشل بعد Cookie Auth.
- `PlatformFontsManager.tsx` يشترط `user.token` قبل الحفظ، وهذا قد يسبب انتهاء جلسة وهمي.
- بعض رسائل الواجهة تظهر كنصوص mojibake داخل ملفات معينة، ويجب مراجعتها تدريجيًا عند لمس الملفات.
- لا يجوز إعلان اكتمال لوحة المدير إلا بعد فحص كل تبويب: عرض، حفظ، تحديث بعد Refresh، وتحقق API.

### 2.2 تسجيل الدخول بالإيميل وكلمة المرور

الموجود:
- `/api/auth/login` موجود ويستخدم `bcrypt.compare`.
- يوجد حماية محاولات فاشلة تقفل الحساب مؤقتًا بعد 5 محاولات.
- الإنتاج لا يرجع token في JSON، بل يعتمد على cookie آمنة.

الاشتباه الأساسي:
- إذا تغير `ADMIN_PASSWORD` في Render بعد إنشاء حساب المدير، خدمة `ensureAdminAccount` لا تعيد ضبط كلمة المرور للحساب الموجود إلا إذا كان `passwordHash` مفقودًا.
- هذا قد يفسر ظهور رسالة "Invalid email or password" رغم أن كلمة المرور في متغيرات البيئة تبدو صحيحة.

قرار الإصلاح:
- نضيف مسار/سكريبت إداري آمن لإعادة ضبط كلمة مرور المدير عند الطلب فقط، أو نعدل seed admin غير الإنتاجي، بدون تغيير كلمة مرور تلقائي عشوائي في كل تشغيل.
- نضيف smoke واضح لتسجيل الدخول: CSRF -> login -> cookie issued -> `/auth/me`.

### 2.3 واتساب والتسجيل

الموجود:
- إعداد WhatsApp Cloud داخل التكاملات.
- إرسال إشعارات واتساب عبر `notificationProviders`.
- اختبار إرسال واتساب من لوحة التكاملات.

الناقص:
- لا يوجد نموذج `PhoneOtp`.
- لا توجد مسارات:
  - `POST /auth/whatsapp/start`
  - `POST /auth/whatsapp/verify`
- لا يوجد زر تسجيل دخول واتساب في `Header.tsx`.

قرار التنفيذ:
- واتساب Auth يكون OTP اختياري، وليس بديلًا إجباريًا للإيميل.
- في المجاني أو بدون Meta، يعمل وضع `console/http provider` للاختبار، ولا نعد بأنه مجاني بالكامل في الإنتاج لأن WhatsApp Cloud له شروط ورسائل وقوالب.

### 2.4 المساعد الذكي

الموجود:
- `server/src/routes/ai.routes.ts` يدعم مزودات:
  - Gemini
  - OpenRouter
  - DeepSeek
  - Qwen
  - OpenAI
  - Ollama
  - LM Studio
  - fallback داخلي
- يوجد تسجيل استخدام في `AiInteraction`.
- يوجد مساعد طالب ومساعد مدير.
- مساعد الطالب يعرف نتائج الطالب ونقاط الضعف من `SkillProgress` و `QuizResult`.

الناقص:
- لا يوجد Knowledge Base واضح لمعلومات المنصة نفسها: الدورات، الباقات، سياسات الدفع، طريقة الاستخدام، الأسئلة الشائعة.
- لا يوجد Budget Guard واضح: حد يومي، حد مستخدم، حد tokens، إيقاف تلقائي عند فشل أو تكلفة.
- لا يوجد اختيار مزود من لوحة المدير محفوظ في قاعدة البيانات، الاعتماد الأكبر على env.
- الواجهة لا تعرض بوضوح أن المزود الحالي `local-fallback` وليس نموذجًا توليديًا حقيقيًا.

قرار التنفيذ:
- بناء AI Provider Router بسيط وآمن فوق الموجود.
- إضافة Knowledge Snapshot من بيانات المنصة العامة فقط.
- منع إرسال مفاتيح أو بيانات إدارية حساسة للمساعد.
- جعل المزود الافتراضي مجاني/صفر تكلفة: fallback داخلي، ثم OpenRouter free/Groq/Gemini عند توفر مفاتيح وحدود.

### 2.5 الملفات والتنظيف

الحالة:
- يوجد 18 ملفًا tracked عليها تعديلات محلية.
- يوجد عدد كبير من ملفات untracked: تقارير دفعات، نتائج load-tests، tmp، وسكريبتات smoke.

قاعدة التنظيف:
- ممنوع حذف أي شيء قبل تصنيفه.
- الملفات التي تحفظ دليل تسليم أو smoke لا تحذف، بل تنقل إلى أرشيف منظم إن لزم.
- مجلد `tmp/` وملفات `tmp_*.json/txt` يمكن تنظيفها بعد التأكد أنها ليست مرجعًا في تقرير تسليم.
- نتائج load-tests تحفظ ملخصاتها فقط، أما ملفات jsonl الثقيلة تؤرشف أو تنظف بعد اعتمادك.

## 3. الخطة المستمرة المناسبة لـ Codex 5.3

### BATCH-A1: تثبيت قاعدة Cookie Auth في لوحة المدير

الهدف:
- إزالة الاعتماد على `user.token` من شاشات الإدارة التي تحفظ إعدادات.

الملفات:
- `dashboards/admin/HomepageManager.tsx`
- `dashboards/admin/PlatformFontsManager.tsx`
- `pages/VerifyEmail.tsx`
- `scripts/smoke-homepage-hero-contract.mjs`
- `scripts/smoke-platform-fonts-contract.mjs`

التحقق:
- `npm run typecheck`
- `npm run smoke:auth-cookie`
- `npm run smoke:csrf`
- `npm run smoke:homepage-hero`
- `npm run smoke:platform-fonts`

الإغلاق:
- حفظ صورة الصفحة الرئيسية، Refresh، التأكد أنها لم تختف.

### BATCH-A2: تشخيص وإصلاح دخول الإيميل/الباسورد

الهدف:
- جعل تسجيل الدخول بالإيميل موثوقًا ومفهوم الرسائل.

الخطوات:
- إضافة smoke إنتاجي آمن: CSRF -> login -> cookie -> `/auth/me`.
- فحص حالة قفل الحساب `loginLockedUntil`.
- إضافة سكريبت إعادة ضبط كلمة مرور مدير بإجراء صريح فقط.
- تحسين رسالة الخطأ عربيًا بدون كشف هل الإيميل موجود أم لا.

التحقق:
- تسجيل دخول صحيح.
- كلمة مرور خاطئة.
- حساب مقفول.
- حساب معطل.
- Forgot/Reset password.

### BATCH-A3: واتساب OTP كمسار تسجيل اختياري

الهدف:
- إضافة تسجيل دخول برقم واتساب بدون كسر الإيميل/جوجل.

الملفات المقترحة:
- `server/src/models/PhoneOtp.ts`
- `server/src/routes/auth.routes.ts`
- `server/src/services/notificationProviders.ts`
- `components/Header.tsx`
- `services/api.ts`

التصميم:
- `POST /auth/whatsapp/start`: يستقبل رقم الهاتف، يولد OTP قصير، يخزنه hash مع مدة صلاحية.
- `POST /auth/whatsapp/verify`: يتحقق من OTP، ينشئ/يربط المستخدم، يصدر cookie.
- Rate limit لكل رقم ولكل IP.
- في وضع التطوير يمكن إرسال OTP إلى console، وفي الإنتاج عبر WhatsApp provider.

### BATCH-A4: المساعد الذكي المجاني والمطلع على المنصة

الهدف:
- مساعد طالب يرد بشكل قريب من ChatGPT، لكن يعرف معلومات الموقع ويظل منخفض التكلفة.

المكونات:
- Provider Router مع ترتيب مزودات:
  - fallback داخلي دائمًا.
  - OpenRouter free عند توفر مفتاح.
  - Groq free/low-cost عند توفر مفتاح.
  - Gemini free tier/low-cost عند توفر مفتاح.
  - Ollama/LM Studio للتشغيل المحلي فقط.
- Budget Guard:
  - حد يومي عام.
  - حد لكل طالب.
  - max tokens.
  - timeout.
  - logging.
  - إيقاف تلقائي عند 429/فشل متكرر.
- Knowledge Snapshot:
  - المسارات.
  - المواد.
  - الدورات المنشورة.
  - الباقات.
  - الأسئلة الشائعة.
  - سياسة الوصول والدفع اليدوي.

التحقق:
- الطالب يسأل: "أبدأ منين؟"
- الطالب يسأل عن دورة/باقة موجودة.
- الطالب يسأل عن نقطة ضعفه.
- المدير يفتح تبويب المساعد ويرى المزود والاستخدام والأخطاء.

### BATCH-A5: فحص لوحة المدير بند بند

الهدف:
- إنشاء مصفوفة قبول لكل تبويب في لوحة المدير.

التبويبات:
- النظرة العامة.
- المسارات والدورات.
- التأسيس.
- التدريب.
- الاختبارات.
- المكتبة.
- المستخدمون.
- المدارس/المجموعات.
- المالية.
- الإعلانات.
- الصفحة الرئيسية.
- الخطوط.
- التكاملات.
- الإشعارات.
- المساعد الذكي.

كل تبويب يجب أن يمر:
- Load.
- Create/Update إن وجد.
- Refresh persistence.
- API consistency.
- Smoke.
- تقرير نتيجة.

### BATCH-A6: تنظيف المشروع باحتراف

الهدف:
- تقليل الفوضى بدون فقد أدلة تسليم.

الخطوات:
- توليد inventory كامل للملفات untracked.
- تصنيف:
  - reports keep/archive.
  - smoke scripts keep if referenced in package.json أو reports.
  - tmp delete.
  - load raw archive.
- تحديث `.gitignore` لمنع رجوع `tmp_*` ونتائج jsonl الثقيلة.
- عدم حذف أي ملف tracked إلا بسبب واضح.

### BATCH-A7: ربط التطوير بعد النقل إلى Hostinger أو استضافة واحدة

القاعدة:
- لا نضع وكيل تطوير داخل الموقع الإنتاجي يملك مفاتيح GitHub أو أسرار السيرفر.

التصميم الآمن:
- الكود يبقى على GitHub.
- الاستضافة تسحب من GitHub أو Docker image.
- الأخطاء تذهب إلى Sentry.
- اللوجات من Render/Hostinger VPS أو Dashboard.
- Codex يطور من نسخة repo على جهازك أو workspace، ثم push.
- GitHub Actions أو سكريبت deploy ينشر تلقائيًا.

لو Hostinger:
- Shared hosting مناسب للواجهة فقط غالبًا.
- VPS من Hostinger مناسب لو تريد Backend + DB proxy + Redis/Ollama صغير.
- MongoDB Atlas يبقى خارجيًا أفضل من تشغيل Mongo على shared hosting.
