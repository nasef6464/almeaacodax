# ALMEAA Testing | بيئة الاختبار المعزولة

تاريخ التجهيز: 2026-10-08

## ما تم إنشاؤه

- فرع مستقل: `test/almeaa-isolated-20261008`، من `main`.
- ملف GitHub Actions: `.github/workflows/almeaa-isolated-testing.yml`.
- MongoDB 7 **مؤقتة داخل GitHub runner**، بقاعدة مختلفة لكل تشغيل (`almeaa_testing_<run_id>`).
- Redis 7 محلية داخل نفس جهاز الاختبار المؤقت.
- واجهة Vite وخادم Node يعملان عبر `127.0.0.1` داخل جهاز GitHub، وليسا منشورين على الإنترنت.
- حسابات ومحتوى تجريبي مُنشأ من `seed:admin` و`seed:operational`، بكلمات مرور عشوائية جديدة لكل تشغيل.
- اختبارات عامة للجوال وسطح المكتب، وصفحات الأدوار، وإنشاء مدرسة وعلاقاتها، وعقود الفصل الذكي، والعمليات الخلفية.
- ملفات النتائج والصور في GitHub Actions Artifacts لمدة 7 أيام.

## الحدود الأمنية الصريحة

1. ممنوع توصيل `MONGODB_URI` بقاعدة Atlas الحقيقية. الحارس الأول يتحقق من أنها `127.0.0.1:27017` واسمها خاص بتشغيل الاختبار.
2. لا تُستخدم أسرار حسابات الإنتاج (Render/Vercel/Cloudflare/Atlas) نهائيًا داخل المسار الجديد.
3. إرسال البريد والواتساب مضبوط على وضع `console`، والذكاء الاصطناعي `none`، ورفع R2 غير مفعّل.
4. لا يوجد نشر تلقائي إلى Render أو Vercel، ولا أي تغيير لفرع `main`.
5. قاعدة البيانات والحسابات التجريبية تختفي عند انتهاء جهاز الاختبار المؤقت.
6. عدم وجود نسخ بيانات إنتاجية مقصود لضمان عزل الطلاب والمدارس الحقيقيين.

## ما لم يُجهّز بعد؟

**لا يوجد حتى الآن رابط اختبار عام مستقل دائم.** الاختبار الحالي آلي ومعزول ومؤقت.
إذا احتاج المالك رابطًا تفاعليًا دائمًا، تُطلب لاحقًا:
- قاعدة بيانات Atlas مختلفة كليًا، ببيانات وهمية، ومستخدم محدود الصلاحيات.
- خدمة Backend منفصلة وFrontend منفصلة **إن سمحت حدود الخطط المجانية**.
- إعدادات CORS/CSRF/Auth وR2/الدفع/البريد بما يمنع استخدامها مع الإنتاج.
- تجربة تشغيل حقيقية وإثبات أن الرحلات الأساسية تعمل على تلك النسخة.

لا تستخدم رابط Render الإنتاجي كهدف لاختبارات إنشاء/حذف الطلاب أو اختبارات الضغط.

## موقف التنفيذ

هذا مسار تجهيز مستقل على فرع غير إنتاجي. لا يُدمج إلى `main` قبل رؤية نجاح التشغيل ومراجعة أثره على خطوط CI القائمة.

## استخدام نسخة تفاعلية محلية على Windows

أضفنا خيارًا منفصلًا عن التشغيل الآلي، مخصصًا لعرض المنصة يدويًا دون أي خدمة سحابية جديدة.

المتطلبات: Docker Desktop على Windows، وكود المشروع على الفرع `test/almeaa-isolated-20261008`.

من نافذة PowerShell داخل مجلد المشروع نفّذ:

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\testing\Start-ALMEAATesting.ps1
```

الملف ينشئ كلمات مرور عشوائية **لحسابات وهمية فقط**، ويضعها محليًا داخل `.env.almeaa-testing.local` غير المتتبع في Git. ثم يبني أربع خدمات معزولة: MongoDB + Redis + Backend + Frontend.

بعد نجاح التشغيل افتح:

**http://localhost:8088**

حسابات التجربة للمدير والمعلم والطالب والمشرف وولي الأمر تظهر في PowerShell بعد التشغيل. لا تستخدمها في الموقع الحقيقي، ولا ترسل كلمات المرور في المحادثة.

لإيقاف النسخة وحذف قاعدة MongoDB المؤقتة وكلمات المرور التي أنشأها المشغّل:

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\testing\Stop-ALMEAATesting.ps1
```

**حماية:** المنافذ `8088` و`4000` تستمع إلى `127.0.0.1` فقط على جهازك. MongoDB وRedis لا تُفتح لهما منافذ على الجهاز؛ البيانات تعيش على تخزين مؤقت في الذاكرة، ولا تُستخدم أسرار Render أو Atlas أو R2 أو Vercel. توقف Docker يحذف بيانات الاختبار، لذلك لا تضع بيانات مهمة هناك.

ملفات التنفيذ: `docker-compose.testing.yml` و`Dockerfile.testing.backend` و`scripts/testing/*.ps1`. اختبار نسخة Docker في CI مستقل باسم **ALMEAA Local Docker Test Stack**. نتيجة هذا الاختبار هي الفيصل قبل اعتبار المسار المحلي مجرّبًا.
