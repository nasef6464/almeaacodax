## قواعد القياس

1. ثلاثة مصادر مستقلة: اختبارات المدرسة، إجابات الحصص، تعلم الطالب الذاتي على المنصة. تظهر جنبًا إلى جنب؛ لا درجة كلية مصطنعة.
2. كل مؤشر يوضح مصدره ومادته وفترته ووحدته وحجم أدلته وآخر تحديث ومدى تغطيته. المحاولات تختلف عن الطلاب الفريدين.
3. دقة الإجابات = الصحيحة / الإجابات المقاسة؛ بلوغ المستهدف = نسبة القياسات التي بلغت الحد المعتمد. لا نخلط بين المؤشرين.
4. المشاهدة والحضور والإنجاز نشاط، وليست وحدها دليل إتقان. لا بيانات، وأدلة غير كافية، وضعف مقاس حالات منفصلة.
5. نحافظ على السياسة والحدود الحالية إلى أن تختبر وتوثق أي سياسة بديلة؛ لا تعديل تاريخي للنتائج أو إعادة تصحيح ضمن هذا العمل.
6. تحليل المحاكي على مستوى المسار يدعم أكثر من مادة داخل القسم؛ مادة السؤال تحدد التحليل، مع إبقاء غير المصنف واضحًا.
7. مقارنة قبل/بعد تتطلب نفس المادة والمهارة وشروط قياس مفهومة. نعرض اختلاف الأسئلة والطلاب وحجم الدليل، ولا ندعي تكافؤ اختبارين دون تحقق.
8. رؤية التعلم الذاتي تلتزم نطاق الحساب والعقد والصلاحيات الحالية؛ لا تتوسع تلقائيًا بسبب تجميع واجهة جديدة.

## رحلة كل مستخدم

| الدور | البداية | الإجراء الأساسي | التفاصيل |
|---|---|---|---|
| الطالب | المطلوب اليوم والتقدم | ابدأ المهمة أو أكملها | اختبارات المدرسة، العلاج، النتائج، المساعدة |
| المعلم | مادتي وفصولي ومهام المتابعة | ابدأ حصة، أنشئ اختبارًا، تابع الطلاب | تحليل مهارة ثم اختيار الطلاب وإسناد نشاط |
| المشرف | مادة/فصل/مصدر/فترة | حدد مجموعة دعم أو إثراء وتابع التنفيذ | مقارنة منصفة، أدلة الطلاب، متابعة المعلمين |
| المدير | ملخص تعليمي قابل للتنفيذ | افتح احتياجًا أو تابع خطة | توزيع الاحتياجات، المسؤولون، المواعيد، نتيجة إعادة القياس |

المعلم يظل محصورًا في مادته وتكليفاته؛ المشرف في جميع المواد المسموحة داخل نطاقه، والمدير في مدرسته. التصفية البصرية لا تحل محل حماية الخادم.
تفاصيل تقرير الاختبار تبقى ثلاثة تبويبات: الملخص، الطلاب، المواد والمهارات. لا إنشاء نسخة منافسة من التقرير الحالي.

## دورة الدعم والإثراء

شرطان سابقان لتنفيذ هذه الدفعة: تحديد موديل/خدمة المهمة القائمة ومدخل الطالب وإشارة الإنجاز وربطها بالتدخل؛ وتوثيق السياسة الحالية للأدلة المؤهلة والحد الأدنى والمقارنة والزمن. لا يختار المنفذ عتبة جديدة أو يوسع صلاحية اعتماد النتيجة من تلقاء نفسه. إذا غابت سياسة مناسبة أو احتاج الربط تغيير دلالة التخزين، يعرض القرار المحدد قبل التنفيذ. الأدلة غير الكافية أو غير القابلة للمقارنة تبقي المتابعة مفتوحة دون حكم تحسن أو إغلاق.

اختيار المصدر والمادة ← مهارة ذات دليل كافٍ ← اختيار الطلاب وتحقق احتياج كل طالب ← محتوى مناسب ← اعتماد المعلم ← مهمة للطالب ← تنفيذ ← إعادة قياس ← مراجعة المسؤول ← إغلاق أو استمرار.

- يبدأ الاختيار من أدلة الطالب أو مجموعة محددة، لا أول مهارة ضعيفة على مستوى المدرسة.
- اختيار الدرس والتدريب بأسماء واضحة مع معاينة ارتباط المهارة وإتاحة المحتوى للطالب. إذا لا يوجد محتوى مناسب نظهر ذلك ونمنع ادعاء وجود خطة مستهدفة.
- توثيق المسؤول والموعد ومصدر baseline والمهارة والمحتوى وحالة المتابعة. يعاد استخدام الموديلات الموجودة؛ أي تعديل تخزين يقدم كتغيير منفصل محدد مع اختبار توافق.
- منع تكرار الإسناد بسبب إعادة المحاولة، وإعادة التحقق من المدرسة والمادة والطلاب عند كل عملية.
- لا إغلاق تلقائي بمجرد فتح فيديو أو إنهاء مهمة؛ اعتماد النتيجة يحتاج دليل إعادة قياس كافيًا وقرارًا واضحًا.
- الإثراء يستخدم الرحلة نفسها بمحتوى أصعب مناسب؛ لا يربط تقدم الطالب بمقارنة علنية محرجة مع زملائه.

## قواعد الواجهة وCSS

- الحفاظ على الشعار والألوان والخط الحالي؛ استخدام مكونات المشروع القائمة قبل إنشاء مكونات إضافية.
- عنوان مختصر، وصف عند الحاجة فقط، إجراء رئيسي واحد لكل سياق، وباقي الإجراءات في مجموعة واضحة.
- شريط فلاتر موحد؛ اختيار المادة قبل المهارات. حفظ اختيار السياق أثناء التنقل دون إظهار بيانات قديمة من سياق سابق.
- بطاقات أرقام قليلة ومختصرة، مع تسمية المصدر؛ التفاصيل والجداول الثقيلة تفتح عند الطلب.
- عناوين مهارات واضحة وتظليل خفيف؛ أزرار الفيديو والتدريب مدمجة وذات مساحة لمس مناسبة.
- استخدام تباعد ومقاسات وحالات موحدة بدل CSS متفرق لكل لوحة. لا ألوان وحدها لنقل الحالة.
- قوائم الصفوف والطلاب مجزأة إلى صفحات مع بحث، وتحميل تفاصيل الطالب عند الطلب؛ لا تحميل كل الطلاب لعرض ملخص.
- الجوال: فلاتر قابلة للطي، تحويل الصفوف العريضة إلى بطاقات عند الحاجة، منع قص الأزرار والنوافذ، وإبقاء الإغلاق والإجراء الأساسي قابلين للوصول.
- دعم RTL ولوحة المفاتيح وتركيز واضح وتسميات للأزرار، واحترام تقليل الحركة. الحركات قصيرة لخدمة الانتقال ولا تعطل العمل.
- حالات تحميل وفراغ وخطأ ونجاح واضحة بالقرب من الفعل؛ لا زر تجميلي بلا وظيفة.

## دفعات التسليم التابعة للخطة الأم

كل دفعة رحلة قابلة للاستخدام والاختبار، وتحدّث حالة Master Control بدل إنشاء سلسلة خطط متنافسة.

### 1. وضوح القياس ورحلة اكتشاف الاحتياج
- [ ] توثيق عقد المؤشرات والحدود والمقام ومصدر الدليل، وإضافة حالات اختبار متعددة المواد والأدلة الناقصة.
- [ ] تحديد تغطية الفترة المختارة بطريقة لا تلغي حدود حماية الخادم ولا تحمل التاريخ كاملًا في المتصفح.
- [ ] توحيد عرض المصدر/المادة/الفترة والتغطية في الملخص والوصول إلى الطالب.
- [ ] تحقق من صفر أدلة، تكرار المحاولات، صفحات تتجاوز حد القراءة، تبديل السياق، وعزل المدارس والأدوار.

### 2. تدخل مستهدف من البداية للنهاية
- [ ] استبدال اختيار أول مهارة عامة بدليل الطالب المختار واختيار المحتوى بالاسم.
- [ ] تنفيذ ربط إسناد المهمة بالمحتوى المقصود اعتمادًا على المالك الحالي، مع تحقق الوصول ومنع التكرار.
- [ ] استكمال إعادة القياس واعتماد النتيجة والإغلاق/الاستمرار بما يتوافق مع الحالات الحالية.
- [ ] اختبار فعلي معزول: معلم يسند ← طالب ينفذ ← إعادة قياس ← مشرف/مدير يتابعان، مع رفض النطاق غير المسموح.

### 3. ملف الطالب وتنظيم اللوحات الأربع
- [ ] إعادة استخدام الملف الحالي وعرض أدلة المصادر الثلاثة منفصلة بحسب المادة.
- [ ] إبراز الإجراء التالي لكل دور وتقليل القوائم المفتوحة والنصوص والأرقام المتكررة.
- [ ] توحيد مكونات العرض والتفاعلات والفراغ والأخطاء عبر الرحلات المتأثرة.
- [ ] فحص متصفح بأدوار فعلية في بيئة معزولة؛ صور ومراجعة قص القوائم والتركيز والنوافذ.

### 4. تحقق المدرسة والإطلاق المتدرج
- [ ] اختبار عرض 360/390/768/1440 بكسل، أسماء عربية طويلة وبيانات فارغة ومتوسطة وكثيفة.
- [ ] اختبارات منطق وتجميع وRBAC وعمليات التدخل، typecheck/build، ثم البوابات المطلوبة على SHA النهائي.
- [ ] قياس الطلبات والصفحات البطيئة على بيانات معزولة ممثلة؛ الاحتفاظ بنتائج الحمل السابقة وحدودها وعدم إعلان سعة إنتاج جديدة.
- [ ] PR مركز لكل دفعة ثم تحقق المنشور بعد مطابقته للنسخة الصحيحة، دون كتابات في بيانات حقيقية أو تكلفة جديدة بلا نطاق مستقل صريح.

## الأداء والخدمات الخارجية

تظهر للمدير جاهزية الخدمة التعليمية: مواد وفصول ومعلمون مكلفون، ومحتوى متاح ووحدات مفعلة بالعقد الحالي، مع إجراء إصلاح واضح عند النقص. تبسط أسماء الخدمات وحالات تفعيلها؛ لا تغيير تسعير أو دفع أو منح محتوى خارج الاستحقاق.

لا نستخدم الذكاء الاصطناعي لحساب النسب أو تقرير الصلاحيات. لا polling أو استدعاء مزود عند فتح اللوحة. التحميل عند الطلب، والتجميع في قاعدة البيانات ضمن نطاق مصرح به. أي rollup أو cache أو فهرس جديد يحتاج قياسًا ومراجعة مستقلة قبل اعتماده.
الأدوات: مهارات owner-execution وgoal-delivery وschools-simple-ux، ثم مهارات تدقيق أزرار المدارس وRBAC وبوابات التحقق عند التنفيذ. المتصفح يفحص الرحلات الفعلية؛ لا تثبيت plugin أو اعتماد جديد بلا حاجة مثبتة. لا تغيير خطة Render المجانية.

## معيار النجاح

يستطيع المعلم تحديد مهارة طالب وإسناد نشاط مناسب دون معرّفات تقنية؛ يجد الطالب المهمة وينفذها؛ يرى المشرف والمدير ما نُفذ ونتيجة القياس ومصدرها. يمكن تفسير كل نسبة دون تخمين. لا تسريب بين المدارس، ولا نسبة صفرية بسبب غياب الأدلة، ولا تراجع في اختبارات المدرسة والحصص القائمة.
تجمع جلسة استخدام مع معلم/مشرف: هل أنجز المهمة دون مساعدة؟ أين تعثر؟ عدد الخطوات والمدة والأخطاء تسجل للمقارنة قبل/بعد، ولا تُختلق أرقام تحسن.
ويشمل التحقق الطالب: العثور على المهمة وبدؤها ورؤية المطلوب التالي؛ والمدير: فهم الاحتياج وتحديد المسؤول والإجراء ومتابعة النتيجة. بذلك يراجع نجاح الواجهة للأدوار الأربعة.
