# تقرير دفعة: تثبيت ملخص طلبات الدفع العالمي + مسح الفلاتر

التاريخ: 2026-05-14
الحالة: مقفول برمجيا + تم فحص البناء والدخان

## الهدف
- منع تضليل الأرقام في شاشة طلبات الدفع بسبب اعتمادها على بيانات الصفحة الحالية فقط.
- إضافة زر سريع لمسح الفلاتر والرجوع للوضع الافتراضي.
- توضيح أن قيم الإيراد داخل بطاقة الطلبات مرتبطة بالفلاتر الحالية.

## ما تم تنفيذه
1. ربط العدادات العامة في الواجهة ببيانات `requestsSummary` (العالمية) عند توفرها:
   - `pendingRequestsCountGlobal`
   - `requestsAllCountGlobal`
2. تحديث مؤشرات KPI بالأعلى لتستخدم الأرقام العالمية بدل أرقام الصفحة الحالية فقط.
3. إضافة زر `مسح الفلاتر` داخل تبويب طلبات الدفع:
   - يعيد الحالة الافتراضية:
     - الحالة: `pending`
     - الدولة: `all`
     - الوسيلة: `all`
     - البحث: فارغ
     - الصفحة: 1
4. إضافة تحميل تلقائي لملخص الطلبات عند فتح الشاشة (ليس فقط عند دخول تبويب الطلبات).
5. توضيح نص بطاقات القيم داخل تبويب الطلبات:
   - “القيمة المعلقة (حسب الفلاتر الحالية)”
   - “الإيراد المعتمد (حسب الفلاتر الحالية)”

## الملفات المعدلة
- `dashboards/admin/FinancialManager.tsx`

## التحقق
- ✅ `npm --prefix server run build`
- ✅ `npm run smoke:payment-providers`
- ⚠️ `npm run typecheck` لم يكتمل (timeout) في البيئة الحالية ويحتاج إعادة تشغيل منفصلة.

## أثر الدفعة
- الأرقام العامة في طلبات الدفع أصبحت أكثر اتساقا مع الملخص الحقيقي.
- المسؤول يقدر يرجع بسرعة لفلاتر الافتراضي بدون إدخال يدوي.
- خفض احتمالية قراءة خاطئة لحالة الطلبات بسبب اعتماد جزئي على بيانات صفحة واحدة.
