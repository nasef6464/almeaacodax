# تدقيق نظام الاختبارات - تقرير معمارية النظام (Assessment System Audit)

## A. الملخص التنفيذي
تم إجراء فحص معماري شامل لنظام الاختبارات بناءً على مراجعة دقيقة للكود الحالي، خصوصاً للمكونات في `dashboards/admin` وملف `store/useStore.ts`. 

**حالة النظام الحالية:**
- النظام يعتمد على مكونات متعددة لإنشاء الاختبارات (`QuizBuilder` القديم، و `UnifiedQuizBuilder` الجديد).
- **البيانات والمعرفات:** تم تصحيح العديد من مسارات الحفظ مؤخراً. الواجهة تعتمد على API للحفظ ولا تقوم بإنشاء معرفات محلية مؤقتة. تعليقات الكود تؤكد ذلك صراحةً: `لا نُنشئ ID محلياً — السيرفر هو مصدر الحقيقة للمعرفات الدائمة`. الدوال في `useStore` (`addQuiz`، `addQuestion`) تستخدم `await api.createQuiz/createQuestion` وتأخذ الـ ID المرتجع من الخادم لتربط العناصر.
- **التوجيه (Assignment):** يُخزّن حالياً داخل نموذج الاختبار نفسه عبر حقول (`targetGroupIds`, `targetUserIds`, `mode`). لا يوجد كيان مستقل للتوجيه بعد.
- **المحاكي مقابل العادي:** يتم التمييز باستخدام `mockExam.enabled` وأيضاً حقل `placement: "mock"` و `showInMock: true`. هذا التكرار يعمل ولكنه عرضة للتشتت إذا لم يتم مزامنته دائماً.

**أهم المشكلات الملاحظة:**
1. **تعدد المنشئات:** تداخل وظيفي بين `QuizBuilder.tsx` و `UnifiedQuizBuilder.tsx` و `MockExamManager.tsx`.
2. **صلاحيات التوجيه:** حقول التوجيه مدمجة داخل الاختبار، مما يعني أن التوجيه ليس كياناً مستقلاً.
3. **تكرار معايير المحاكي:** الاعتماد على `placement` بالإضافة إلى خصائص `mockExam` لتحديد نوع الاختبار.
4. **تشتت الإعدادات:** أسماء الإعدادات واختلافها المحتمل في الواجهة.
5. **تحديث البيانات:** رغم الاعتماد على السيرفر، بعض الأخطاء قد لا تمنع الواجهة من سلوك متفائل جزئياً (Optimistic Updates)، لكنها في الغالب تُدار عبر إرجاع الـ Error.

## B. خريطة النظام الحالية

| المكون / الملف | الوظيفة | ملاحظات وحالة الاستخدام |
|---|---|---|
| `UnifiedQuizBuilder.tsx` | منشئ الاختبارات الموحد | يتعامل مع العادي والتدريبات والمحاكي، ويستخدم `SmartQuestionSelector`. يبدو أنه الأحدث والأكثر توحيداً. |
| `QuizBuilder.tsx` | منشئ الاختبارات القديم | ما زال موجوداً ويُستدعى في أماكن متعددة. يحتوي على توليد أسئلة عبر AI ويدير إعدادات مشابهة. |
| `MockExamManager.tsx` | إدارة محاكيات القدرات والتحصيلي | يعتمد على نافذة إنشاء خاصة أو يستدعي المنشئ الموحد. يدير الأقسام. |
| `QuizzesManager.tsx` | مركز الاختبارات والتوجيه | يعرض جدول الاختبارات العادية والموجهة. يدير استدعاء `UnifiedQuizBuilder` للإنشاء والتعديل. |
| `SmartQuestionSelector.tsx` | اختيار الأسئلة للاختبار | تم توحيده ليعتمد على API مباشرة (يستخدم `api.getQuestions` مع تمرير `sectionId` أو `pathId` بدلاً من الاعتماد على الـ Store فقط). |
| `UnifiedQuestionBuilder.tsx` | منشئ الأسئلة الموحد | مكون واجهة لإنشاء سؤال مفرد، يُحفظ عبر المكون الأب. |
| `QuestionBankManager.tsx` | مركز إدارة بنك الأسئلة | يعرض جميع الأسئلة، ويسمح بالاستيراد (Excel)، ويستدعي `UnifiedQuestionBuilder` للإضافة والتعديل عبر `addQuestion`. |
| `useStore.ts` | إدارة الحالة والتخزين المحلي | يوفر دوال `addQuiz`, `updateQuiz`, `addQuestion`. هذه الدوال موصولة بشكل صحيح بالـ API وتعتمد على الرد (Awaited). |

## C. دورة الحياة الحالية

- **الاختبار العادي / التدريب:** يُنشأ عبر `UnifiedQuizBuilder` -> اختيار المادة/المسار -> إضافة أسئلة من `SmartQuestionSelector` (يجلب من API) -> حفظ (ينتظر رد الـ API ليأخذ الـ ID).
- **اختبار المحاكي:** يُضاف كـ Quiz ولكن بتحديد حقل `mockExam.enabled = true` و `placement = "mock"`. الأسئلة تُربط بالأقسام (`mockExam.sections[].questionIds`).
- **التوجيه (Assignment):** إذا أردنا توجيه الاختبار لمجموعة، نقوم بتعديل `targetGroupIds` / `targetUserIds` داخل وثيقة الـ Quiz ذاتها (ليس كوثيقة جديدة منفصلة).

## D. جدول المشكلات المؤكدة

| الرقم | المشكلة | الوصف والخطورة | الحل المقترح لاحقاً |
|---|---|---|---|
| 1 | دمج التوجيه بالاختبار | لا يوجد كيان `ExamAssignment` منفصل. يتم تعديل الـ Quiz لإضافة مجموعات. (خطورة: متوسطة) | إنشاء كيان `ExamAssignment` في المستقبل لفصل محتوى الاختبار عن تكليفه. لا ينصح بتنفيذه في المرحلة الحالية. |
| 2 | تكرار منشئ الاختبار | وجود `QuizBuilder` و `UnifiedQuizBuilder`. (خطورة: منخفضة-متوسطة) | التخلص التدريجي من `QuizBuilder` واستبداله بـ `UnifiedQuizBuilder` بالكامل بعد ضمان دعم جميع ميزاته. |
| 3 | تصنيف المحاكي | يتم الاعتماد على 3 حقول أحياناً: `mockExam.enabled`, `placement === "mock"`, و `showInMock`. (خطورة: متوسطة) | توحيد الاستعلام بمتغير منطقي مركزي في الواجهة يعتمد فقط على `mockExam.enabled` أو حقل `quizKind` صارم. |

## E. خطة التنفيذ وتوصيات العمل

بناءً على الفحص، **لا توجد أعطال حرجة تتعلق بحفظ الأسئلة الوهمية أو فقدان المعرفات (تم حلها وتثبيتها سابقاً في الكود بواسطة فريق التطوير).** 

أقترح أن تركز **المرحلة القادمة** على ما طلبه المستخدم في المتطلبات قيد الانتظار قبل هذه الوثيقة:
- **ج — توحيد تمييز الاختبار العادي vs المحاكي**: توحيد مؤشرات الـ UI بناءً على الحقل المركزي وتخفيف الاعتماد على حقول ثانوية مكررة.
- **د — لوحة نتائج الاختبارات الموجهة للمشرف**: بناء أو تحسين عرض نتائج الاختبارات التي قام المشرف بتوجيهها.

لن نقوم بإعادة بناء كاملة أو تنفيذ كيان التوجيه المنفصل (`ExamAssignment`) في هذه المرحلة للحفاظ على استقرار البيانات القديمة.
