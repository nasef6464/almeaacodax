## 2. معايير أمان وحماية الـ APIs (Security & Quality Standards)

1. **التحقق من صحة المدخلات (Strict Schema Validation via Zod):**
   - لا يتم تمرير أي طلب إلى دوال المعالجة (Controllers) دون المرور على مخطط Zod صارم يفحص الحقول وأنواع البيانات ويمنع الحقول الزائدة غير المصرح بها (`strip` / `strict`).
   - تم التحقق من سلامة كافة المخططات، مثل `contentBootstrapPhaseSchema` التي تقبل فقط القيم المعتمدة (`full` أو `core`).

2. **طبقة المصادقة والجلسات (Authentication Middleware):**
   - الاعتماد على ملفات تعريف ارتباط مشفرة ومؤمنة (`HttpOnly`, `SameSite=Lax`, `Secure` في الإنتاج).
   - حماية ضد هجمات تزوير الطلبات عبر المواقع (Double-Submit CSRF Token).

3. **معالجة الأخطاء الموحدة (Standardized Error Response):**
   - تم توحيد نمط الخطأ عبر `AppError` وميدلوير مركزي:
     ```json
     {
       "success": false,
       "error": {
         "code": "VALIDATION_ERROR",
         "message": "تفاصيل الخطأ بوضوح للمستخدم",
         "details": []
       }
     }
     ```
   - إخفاء تفاصيل المسارات البرمجية وStack Traces في بيئة الإنتاج لمنع تسريب المعلومات الأمنية.

4. **تحديد معدل الطلبات (Rate Limiting):**
   - حماية مسارات تسجيل الدخول بـ Rate Limiter صارم (5 محاولات لكل IP في 15 دقيقة) لمنع هجمات القوة الغاشمة (Brute Force).
   - حماية مسارات إرسال الإجابات في الحصص الذكية لمنع الإغراق (Spamming).
