## 1. البنية التحتية لقاعدة البيانات (Database Infrastructure)
- **المحرك:** MongoDB v7.0+ (متصل عبر Mongoose ODM v8.9).
- **عدد النماذج المفهرسة (Mongoose Models):** 32 نموذجاً مستقلاً.
- **استراتيجية الاتصال:** اتصال مجمّع (Connection Pooling) مع دعم إعادة المحاولة التلقائية (Auto-Reconnect) وخوارزمية Exponential Backoff للتعافي من الانقطاعات المؤقتة.

## 2. النماذج الرئيسية وهيكل العلاقات (Core Schema Architecture)

1. **إدارة المستخدمين والمؤسسات (`User`, `Group`, `B2BPackage`):**
   - **`User`:** يحفظ الهوية والبريد والاسم والدور (`role`)، بالإضافة إلى مصفوفات الربط: `groupIds` (للمشرفين والطلاب) و `studentIds` (لأولياء الأمور) و `schoolId`.
   - **`Group`:** تمثل المدرسة أو الفصل الدراسي، وتحتوي على قائمة المشرفين `supervisorIds` ومعرف المدرسة الأم.
   - **فهارس الأداء:** فهرس مركب `{ email: 1 }` (Unique)، وفهرس `{ role: 1, schoolId: 1 }` لتسريع استعلامات الإشراف والمدارس.

2. **بنك الأسئلة والمحتوى التعليمي (`Question`, `Quiz`, `Topic`, `Lesson`):**
   - **`Question`:** يدعم أنواع الأسئلة المتعددة (اختيار من متعدد، صح/خطأ، مقالي) مع تخزين صيغ KaTeX الرياضية وروابط الوسائط المشفرة.
   - **`Quiz`:** يربط بين المسار التعليمي والأسئلة المختارة مع حفظ معايير الوقت والدرجات وسياسة الإعادة.
   - **فهارس الأداء:** فهرس `{ subjectId: 1, topicId: 1, difficulty: 1 }` لتسريع منشئ الاختبارات الذكي بنظام الصفحات `searchPage`.

3. **الحصص الذكية التفاعلية (`ClassroomSession`, `ClassroomResponse`):**
   - **`ClassroomSession`:** تسجل كود الانضمام السريع `pin` (مفهرس مع انتهاء صلاحية TTL تلقائي)، وحالة السؤال الحالي `activeQuestionIndex`، وقائمة الطلاب المتصلين.
   - **`ClassroomResponse`:** تسجل إجابات الطلاب التفاعلية بدقة وتمنع التكرار عبر فهرس مركب فريد `{ sessionId: 1, questionId: 1, studentId: 1 }`.

4. **النتائج والتقارير (`QuizResult`, `StudyPlan`, `WeakSkill`):**
   - **`QuizResult`:** حفظ الإجابات والدرجات والوقت المستغرق مع روابط للمهارات المرتبطة بكل سؤال.
   - **فهارس الأداء:** فهرس مركب `{ studentId: 1, quizId: 1, createdAt: -1 }` لسرعة جلب تاريخ نتائج الطالب.

## 3. التدقيق الصحي ومنع السجلات اليتيمة (Orphan Prevention & Integrity)
- **منع السجلات المعلقة (Orphaned Records):** تم تفعيل خطافات Mongoose (Pre/Post Middleware) لحذف أو تحديث ارتباطات الفصول تلقائياً عند تغيير دور المستخدم أو حذف الفصل.
- **سلامة الأنواع (Type Safety):** تم ربط نماذج Mongoose بمخططات TypeScript المشتركة لضمان تطابق كامل بين بيانات السيرفر والواجهة ومنع تلوث الحقول بـ `any`.
- **اختبار التعافي من انهيار الاتصال (Recovery Gate):**
  - تم إجراء محاكاة لقطع الاتصال بقاعدة البيانات وإعادته في بوابة `Platform V3 Recovery Gate`.
  - **النتيجة:** نجاح تام في إعادة الاتصال دون الحاجة لإعادة تشغيل خادم Node.js مع تفريغ آمن لطلبات الانتظار (Queue Flush).
